With DanyWhere you don't have to decide before you speak what should happen to your words. You start every dictation the same way and choose at the end: the keys you press to stop also say whether a space or a new paragraph follows, and whether a chat message goes out right away. One more key, pressed before the end, lets you tell a language model what to do with the text. This chapter shows the four lists of key combinations behind all this, what a new installation brings, and how to set up your own.

## Four lists of the same kind

Under **Defaults › General**, four lists follow each other:

- **Start Shortcuts** start a recording with a tap. It runs until an end shortcut ends it.
- **Hold Shortcuts** record while you hold them. Letting go ends the recording the way the entry says.
- **Instruction Shortcuts** switch a running recording from the text to an instruction: what you say next tells post-processing what to do with the text, such as “translate this into Polish”. [The spoken instruction](../spoken-instruction/) explains them.
- **End Shortcuts** end a running recording the way the entry says.

A start shortcut is only a key combination. Hold, instruction and end shortcuts have the same parts, described further down: a name, a key combination, **Append** and **Send Context**.

DanyWhere takes the start and hold shortcuts all the time. The instruction and end shortcuts it takes only while a recording runs, as it does with <kbd>Esc</kbd>. That's why <kbd>↩</kbd> can end a dictation and <kbd>⇥</kbd> can switch to the instruction without getting in your way: the rest of the time, the keys do what they always do.

## What a combination does

What a key combination does follows from the lists it stands in. The same combination may stand in several lists; within one list, no two entries can share one.

| The combination is … | Without a recording | During a recording |
|---|---|---|
| a start shortcut | A tap starts a recording that keeps running. | It ends the recording like the end shortcut with the same combination, and does nothing if there is none. |
| a hold shortcut | Holding records; letting go ends the recording with this entry's values. A short tap does nothing. | As for a start shortcut. |
| a start and a hold shortcut | A short tap starts a recording that keeps running; holding records until you let go. | As for a start shortcut. |
| an instruction shortcut | Nothing: the key goes to the app. | It switches to the instruction. |
| an end shortcut | Nothing: the key goes to the app. | It ends the recording with this entry's values. |

An instruction shortcut may have a start or hold shortcut's combination: without a recording, the key starts one; during a recording, it switches to the instruction. It can't have an end shortcut's combination, since both are taken only during a recording.

## Tap, hold, or both

DanyWhere tells a tap from a hold by how long you press the keys. A combination that is a start and a hold shortcut does both. On a Mac, tap <kbd>⌃ Space</kbd> and talk for as long as you like, then tap it again; or hold it while you speak and let go when you're done.

A short tap on a hold shortcut that isn't also a start shortcut discards the recording: nothing is transcribed, inserted or kept. So a key pressed by mistake has no effect. The lists say under each entry what it does: **Also a hold shortcut** under a start shortcut, and under a hold shortcut **Also a start shortcut: a short tap starts a recording that keeps running.** or **Hold shortcut only: a short tap does nothing.**

Instruction shortcuts know both ways too. Tap one, and an end shortcut sends the dictation off. Hold it while you speak the instruction, and letting go sends it off.

## What hold, instruction and end shortcuts are made of

Each entry has these parts:

- **Name:** how the list shows it. An end shortcut without a name of its own shows its key combination. A hold or instruction shortcut shows its combination with “held”, such as **⌃ Space held**, since its values say what happens when you let go.
- **The key combination.** Every entry needs one.
- **Append:** what comes after the text. In the text field, `\s` is a space, `\n` a line break and `\t` a tab; anything else is appended as written. Next to it, you can choose a key press such as Enter, which is sent after the text has been pasted. A line underneath says in words what will be appended.
- **Send Context:** earlier dictations from the same window go along, so the model knows what you've been writing about. This only counts when the dictation is post-processed.

Whether a dictation is post-processed is not up to the entry. It's up to **Post Processing** under **Defaults › Advanced**, set to **With Instruction Shortcut** out of the box: then a dictation is post-processed when you press an instruction shortcut during it. [The spoken instruction](../spoken-instruction/) shows all three choices.

## The shortcuts of a new installation

<Tabs syncKey="os">
<TabItem label="macOS">

On a Mac, one combination starts and holds, and the end shortcuts follow one rule:

- <kbd>⇧</kbd> (Shift) picks the smaller variant: no space instead of a space, a line instead of a paragraph.
- <kbd>⌃</kbd> (Control) together with <kbd>↩</kbd> (Return) presses a key instead of appending text.

| List | Combination | Name | What follows the text |
|---|---|---|---|
| **Start Shortcuts** | <kbd>⌃ Space</kbd> | | |
| **Hold Shortcuts** | <kbd>⌃ Space</kbd> | **⌃ Space held** | a space |
| | <kbd>⌃⇧ Space</kbd> | **⌃⇧ Space held** | nothing |
| **Instruction Shortcuts** | <kbd>⇥</kbd> (Tab) | **⇥ held** | a space |
| **End Shortcuts** | <kbd>⌃ Space</kbd> | **Space** | a space |
| | <kbd>⌃⇧ Space</kbd> | **No space** | nothing |
| | <kbd>↩</kbd> | **Paragraph** | two line breaks |
| | <kbd>⇧↩</kbd> | **Line** | one line break |
| | <kbd>⌃↩</kbd> | **Send Enter** | a press of Enter |
| | <kbd>⌃⇧↩</kbd> | **Send Shift+Enter** | a press of Shift+Enter |

All of them have **Send Context** ticked, so a post-processed dictation sees what you wrote before in the same window.

In practice: for a longer text, tap <kbd>⌃ Space</kbd> to start and again to end; each piece gets its space, ready for the next. Or hold it while you speak. In an email, end with <kbd>↩</kbd> and the next paragraph is ready. In a chat, <kbd>⌃↩</kbd> sends the message; tap <kbd>⇥</kbd> before it and say “a bit friendlier”, and the message is polished first.

</TabItem>
<TabItem label="Windows">

Windows starts with <kbd>Ctrl+Space</kbd> as start and hold shortcut, <kbd>Ctrl+Shift+Space</kbd> as a second hold shortcut, and <kbd>Tab</kbd> as instruction shortcut. Two end shortcuts have the combinations of the two hold shortcuts. None of them appends anything, so you tap <kbd>Ctrl+Space</kbd> again to end, or hold it and let go.

For anything else, add end shortcuts of your own, as shown further down.

</TabItem>
<TabItem label="Linux">

Linux starts with <kbd>Ctrl+Alt+Space</kbd> as start and hold shortcut and <kbd>Ctrl+Alt+Shift+Space</kbd> as a second hold shortcut. Two end shortcuts have these combinations. None of them appends anything.

Linux has no instruction shortcuts, and a recording ends only through a start or hold shortcut. See the limits at the end of this chapter.

</TabItem>
</Tabs>

:::note
These are the factory settings of a new installation. If you used DanyWhere before, an update keeps your own end shortcuts; the twelve end shortcuts a Mac used to start with become the six above. The names are written once, in your system's language at the first start, and you can rename them as you like.
:::

## Add or change a shortcut

You'll find all four lists under **Defaults › General**.

<Screenshot
  name="end-shortcuts"
  alt="The End Shortcuts group under Defaults › General. Each end shortcut is a block with its name, its key combination, the Append field with a selection for the key press, and the checkbox Send Context, starting with Space and No space, which have the combinations of the hold shortcuts."
  caption="The end shortcuts under Defaults › General."
/>

Each list has its button: **Add Start Shortcut**, **Add Hold Shortcut**, **Add Instruction Shortcut** and **Add End Shortcut**. Click it and press the combination you want; then set what the entry does. To change a combination, click it and press the new one. The trash icon next to it deletes an entry. One start or hold shortcut always stays, so a recording can always be started, and one end shortcut, so it can always be ended. The instruction shortcuts may be none at all.

A profile can differ from the defaults. On the profile's own page **General**, change an entry of any of the four lists, add one or delete one, and only that entry becomes the profile's own. All others keep following the defaults, including your later changes there. [Defaults and profiles](../defaults-and-profiles/) shows how this works for every setting.

## Recipe: send a chat message right away

In a chat, you usually want to say your message and have it sent, without reaching for the mouse. An end shortcut that presses Enter after the text does exactly that.

<Steps>

1. Open **Defaults › General** and scroll to **End Shortcuts**.

2. Click **Add End Shortcut** and press the combination you want to send with, for example <kbd>Ctrl+Enter</kbd> on Windows or <kbd>⌘↩</kbd> on a Mac.

3. Under **Append**, leave the text field empty and choose **Enter** as the key press (<kbd>↩</kbd> on a Mac).

4. Tick **Send Context** if a polished message should see what was said before.

5. Give it a name you'll recognize, such as `Send`.

6. Try it: in a chat, start a dictation, say your message and end with the new combination. The text appears and is sent. To have it polished first, tap the instruction shortcut before you end, and say what to do or nothing at all.

</Steps>

:::tip
On a Mac, a new installation already has this: <kbd>⌃↩</kbd> sends the message. Tap <kbd>⇥</kbd> before it, and the message is polished first.
:::

## Limits

:::caution[Linux]
On Linux, DanyWhere can't take a combination only while a recording runs. So it takes no end shortcut's own combination and has no instruction shortcuts. A recording ends there when you let go of a hold shortcut, or tap a start shortcut again whose combination an end shortcut has; the settings won't let you remove the last such end shortcut. For the recipe above, give the Enter key press to an end shortcut with a start shortcut's combination, or to a hold shortcut. To post-process on Linux, set **Post Processing** to **Always**, in a profile of its own if you like.
:::

**On a Mac without Accessibility**, DanyWhere can't press keys. If you continue without the permission, a new installation leaves out the two end shortcuts that send Enter or Shift+Enter, and a key press chosen under **Append** isn't sent.

**macOS uses <kbd>⌃ Space</kbd> itself** to switch input sources once you have more than one. If you switch keyboard layouts that way, turn the shortcut off in System Settings, under Keyboard › Keyboard Shortcuts › Input Sources, or give DanyWhere other combinations.
