With DanyWhere you don't have to decide before you speak what should happen to your words. You start every dictation the same way and choose at the end: the keys you press to stop also say whether a space or a new paragraph follows, whether a language model polishes the text, and whether a chat message goes out right away. This chapter shows the end shortcuts a new installation brings, what each one is made of, and how to set up your own.

## Start shortcuts start, end shortcuts end

A **Start Shortcut** only starts a recording. An end shortcut only ends one, and DanyWhere takes its combination only while a recording runs, as it does with <kbd>Esc</kbd>. That's why <kbd>↩</kbd> can end a dictation without getting in your way: the rest of the time, the key does what it always does.

Every way to end decides the same three things: what comes after the text, whether the text is post-processed, and whether earlier dictations go along as context.

## The end shortcuts of a new installation

<Tabs syncKey="os">
<TabItem label="macOS">

On a Mac, twelve end shortcuts follow one rule, so the keys already tell you what each one does:

- <kbd>⌥</kbd> (Option) post-processes the text.
- <kbd>⇧</kbd> (Shift) picks the smaller variant: no space instead of a space, a line instead of a paragraph.
- <kbd>⌃</kbd> (Control) together with <kbd>↩</kbd> (Return) presses a key instead of appending text.

| Combination | Name | What follows the text |
|---|---|---|
| <kbd>⌃ Space</kbd> | **Direct · Space** | a space |
| <kbd>⌃⇧ Space</kbd> | **Direct · No space** | nothing |
| <kbd>↩</kbd> | **Direct · Paragraph** | two line breaks |
| <kbd>⇧↩</kbd> | **Direct · Line** | one line break |
| <kbd>⌃↩</kbd> | **Direct · Send Enter** | a press of Enter |
| <kbd>⌃⇧↩</kbd> | **Direct · Send Shift+Enter** | a press of Shift+Enter |

The same six with <kbd>⌥</kbd> in front, from <kbd>⌥⌃ Space</kbd> to <kbd>⌥⌃⇧↩</kbd>, are called **Post-processed · Space** and so on. They post-process the text and send earlier dictations from the same window along as context.

In practice: for a longer text, tap <kbd>⌃ Space</kbd> to start and again to end; each piece gets its space, ready for the next. In an email, end with <kbd>↩</kbd> and the next paragraph is ready. In a chat, <kbd>⌃↩</kbd> sends the message, and <kbd>⌥⌃↩</kbd> polishes it first.

Letting go of a held start shortcut appends a space. With the **Second Start Shortcut**, the text is post-processed as well.

</TabItem>
<TabItem label="Windows">

Windows starts with two end shortcuts that have the combinations of the two start shortcuts: <kbd>Ctrl+Space</kbd> ends without post-processing, <kbd>Ctrl+Shift+Space</kbd> with it. Neither appends anything, so you press the start shortcut again to end, and choose the second one when you want the text polished.

Letting go of a held start shortcut works the same way: the **Start Shortcut** ends without post-processing, the **Second Start Shortcut** with it.

For anything else, add end shortcuts of your own, as shown further down.

</TabItem>
<TabItem label="Linux">

Linux starts like Windows, with two end shortcuts that have the combinations of the two start shortcuts: <kbd>Ctrl+Alt+Space</kbd> ends without post-processing, <kbd>Ctrl+Alt+Shift+Space</kbd> with it. Neither appends anything.

Letting go of a held start shortcut works the same way: the **Start Shortcut** ends without post-processing, the **Second Start Shortcut** with it.

On Linux, a recording can only end through a start shortcut. See the limits at the end of this chapter.

</TabItem>
</Tabs>

:::note
These are the factory settings of a new installation. If you used DanyWhere before, an update leaves your end shortcuts as they were. The names are written once, in your system's language at the first start, and you can rename them as you like.
:::

## What an end shortcut is made of

Each entry under **End Shortcuts** has these parts:

- **Name:** how the list shows it. Until you type a name, it shows the key combination.
- **The key combination** that ends the recording this way. Every end shortcut needs one, and no two can share one.
- **Append:** what comes after the text. In the text field, `\s` is a space, `\n` a line break and `\t` a tab; anything else is appended as written. Next to it, you can choose a key press such as Enter, which is sent after the text has been pasted. A line underneath says in words what will be appended.
- **Post-process:** a language model polishes the text before it arrives, with the prompts that are active in the profile. This only works while **Post Processing** is switched on under **Defaults › Advanced**; if it isn't, the entry says so.
- **Send Context:** only with post-processing. Earlier dictations from the same window go along, so the model knows what you've been writing about.

## The start shortcuts and how they end

**Pressing a start shortcut again** during a recording ends it only through an end shortcut with exactly its combination. The list points out such an entry with a line under it. If no end shortcut has the combination, pressing the start shortcut does nothing while a recording runs.

**When Held**, at the top of **End Shortcuts**, sets how letting go of a held start shortcut ends the recording. Each start shortcut has its own: **Append**, **Post-process** and **Send Context**, but no name and no combination. While **Shortcut Behavior** is **Toggle**, nothing is held, so **When Held** is hidden.

The **Second Start Shortcut** is optional: a second combination that starts a recording, <kbd>⌃⇧ Space</kbd> on a Mac. DanyWhere takes it only while post-processing is switched on. It's made for holding: hold <kbd>⌃ Space</kbd> for the plain text, hold <kbd>⌃⇧ Space</kbd> for the polished one.

## Add or change an end shortcut

You'll find the end shortcuts under **Defaults › General › End Shortcuts**.

<Screenshot
  name="end-shortcuts"

Below it, each end shortcut is a row with its name, its key combination, the same field, selection and checkboxes, starting with the two that have the start shortcuts' combinations."
  caption="The end shortcuts under Defaults › General."

To add one, click **Add End Shortcut** and press the combination you want; then set what it does. To change a combination, click it and press the new one. The trash icon next to it deletes an entry. One end shortcut always stays, so a recording can always be ended.

A profile can differ from the defaults. On the profile's own page **General**, change an end shortcut, add one or delete one, and only that entry becomes the profile's own. All others keep following the defaults, including your later changes there. [Defaults and profiles](../defaults-and-profiles/) shows how this works for every setting.

## Recipe: send a chat message right away

In a chat, you usually want to say your message and have it sent, without reaching for the mouse. An end shortcut that presses Enter after the text does exactly that.

<Steps>

1. Open **Defaults › General** and scroll to **End Shortcuts**.

2. Click **Add End Shortcut** and press the combination you want to send with, for example <kbd>Ctrl+Enter</kbd> on Windows or <kbd>⌘↩</kbd> on a Mac.

3. Under **Append**, leave the text field empty and choose **Enter** as the key press (<kbd>↩</kbd> on a Mac).

4. If the model should polish the message first, tick **Post-process**, and **Send Context** if it should see what was said before.

5. Give it a name you'll recognize, such as `Send`.

6. Try it: in a chat, start a dictation, say your message and end with the new combination. The text appears and is sent.

</Steps>

:::tip
On a Mac, a new installation already has this: <kbd>⌃↩</kbd> sends the message, <kbd>⌥⌃↩</kbd> polishes it first.
:::

## Limits

:::caution[Linux]
On Linux, DanyWhere can't take an end shortcut's own combination during a recording. A recording ends there by letting go of a held start shortcut, or by pressing a start shortcut again whose combination an end shortcut has. So for the recipe above, give the Enter key press to an end shortcut that has a start shortcut's combination, or to **When Held**. The settings won't let you remove the last way to end: keep an end shortcut with a start shortcut's combination, or choose **Hold**.
:::

**On a Mac without Accessibility**, DanyWhere can't press keys. If you continue without the permission, a new installation leaves out the four end shortcuts that send Enter or Shift+Enter, and a key press chosen under **Append** isn't sent.

**macOS uses <kbd>⌃ Space</kbd> and <kbd>⌥⌃ Space</kbd> itself** to switch input sources. If you switch keyboard layouts that way, turn those shortcuts off in System Settings, under Keyboard › Keyboard Shortcuts › Input Sources, or give DanyWhere other combinations.
